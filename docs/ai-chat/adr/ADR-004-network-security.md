# ADR-004: 网络通信安全方案

**日期**：2026-03-05  
**状态**：已批准  
**架构师**：架构师智能体

## 上下文

Jedi AI Chat 需要与多个第三方 API 通信：
- OpenAI API
- Anthropic API
- 其他模型提供商 API
- MCP 远程服务器

网络通信安全缺陷可能导致：
- 中间人攻击
- API Key 窃取
- 数据篡改
- 拒绝服务

## 决策

强制 HTTPS，配置合理的超时和重试策略，MVP 阶段暂不实施证书固定。

## 备选方案

### 方案 1：仅 HTTPS（选中，MVP）
- **优点**：实现简单，维护成本低
- **缺点**：依赖系统 CA，存在理论上的中间人攻击风险

### 方案 2：HTTPS + 证书固定（后续版本）
- **优点**：最强的通信安全
- **缺点**：证书更新时需要发布新版本，维护成本高

### 方案 3：双向 TLS（否决）
- **优点**：双向认证
- **缺点**：实现复杂，第三方 API 不支持

## 理由

1. **MVP 优先**：先实现基础安全，快速交付
2. **成本收益**：证书固定增加维护成本，收益在 MVP 阶段不明显
3. **灵活性**：后续可以根据需要添加证书固定
4. **依赖管理**：系统 CA 通常是安全的，攻击难度高

## 后果

### 正面
- 实现简单
- 维护成本低
- 足够应对大多数威胁

### 负面
- 依赖系统 CA 存储
- 理论上存在 CA 被攻破的风险
- 后续添加证书固定需要重构

## 实现细节

### 安全配置
- **强制 HTTPS**：禁用 HTTP
- **超时设置**：连接超时 10s，请求超时 30s
- **TCP Keepalive**：60s
- **禁用压缩**：防止 CRIME/BREACH 攻击
- **连接池**：最大 5 个空闲连接

### 依赖
- `reqwest` crate（with rustls）
- `rustls` crate

### 代码结构
```
src-tauri/src/network/
├── client.rs     # 安全 HTTP 客户端
├── config.rs     # 网络配置
└── mod.rs
```
